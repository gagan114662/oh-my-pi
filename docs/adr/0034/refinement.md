# Bounded model-to-Rust correspondence

`crates/tui/tests/elastic_refinement.rs` replays two traces generated by the
original `ElasticSlots.tla` actions through the public production `Slots` API.
The expected history, lifecycle, emitted counters and commit frontier come from
TLC states, rather than a second Rust implementation of the model. Each delivered
plan is rendered through the real component/frame pipeline and its physical rows
are compared with the model's Wide semantic rows before acknowledgement.

The profiles cover mutable speculation, a later block finalizing before its
predecessor, ordered batch retirement, append-only prefix emission, finalization
of a partially emitted head, and retirement of its remaining suffix. Both check
that planning and viewport rendering leave committed history unchanged.

The abstraction is deliberately limited:

- Model Wide maps to width 32 with the unwrapped `row-a`/`row-b` alphabet.
- Model Create followed by Admit maps to `Slots::open` at admission. Queued
  allocation and animated viewport scheduling are not checked here.
- BeginFlush is a scheduler stutter because `Slots::plan` already stages
  finalized rows; only the acknowledgement commits them.
- The model resets emitted counts on retirement. Rust retains those counts, so
  the abstraction projects a committed block's emitted count to zero.
- Resize/replay, width doubling, custom roots, partial-write fail-stop,
  finalized-snapshot repair and shutdown are outside these profiles. This is
  not a complete implementation refinement proof or a replacement for the
  existing model configurations and property tests.

Regenerate and verify the trace artifact with the pinned TLC 1.8.0 jar:

```sh
python3 scripts/generate-elastic-refinement.py \
  --jar target/tlc-tools/tla2tools-1.8.0.jar --check
```

The script creates a temporary driver selecting original model actions. It keeps
all original safety invariants. An additional `TraceNotFinished` sentinel is
intentionally violated only at the requested final state to trigger TLC's JSON
trace export; a different violation, missing step or failure to reach that state
fails generation. This sentinel is trace extraction, not a reported defect in the
model. Original temporal-property checking remains in the five normal TLC runs.
CI regenerates the checked-in expected states and separately runs the compiled
Rust replay, retaining both sets of evidence.

A meaningful negative control is to remove the actual history insertion
`self.history.push(planned.logical.clone());` in `Slots::commit_normal` in an
isolated mutation branch. The unchanged replay must fail at the first acknowledged
row even though the emitted counter and lifecycle still advance. That is a
production implementation mutation, not an altered expected fixture. A hosted
red-before/green-after run is required before claiming this sensitivity was
executed; source inspection alone is not that evidence.
